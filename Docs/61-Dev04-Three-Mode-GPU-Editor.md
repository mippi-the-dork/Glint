# Dev04 — Schematic, Rendered, and Hybrid

**Status:** Implemented in source; Unreal Editor/SM6 run and the resulting GPU texture have **not** been validated locally. UE5.8.0–5.8.3/Win64 targeted.

## Model

The three modes operate on the *same* `UGlintFlare` asset and selected element index. Schematic draws editable source/axis relationships using Slate geometry. Rendered draws a `UTextureRenderTarget2D` updated by `FGlintPreviewCS` through the Render Dependency Graph (RDG). Hybrid draws the actual GPU texture as its background, then paints the schematic markers, axes, and selection highlights above it. Switching modes does not recreate the asset, reset source position, or change selected element.

Unlike the prior schematic-only 0.3 editor, **Rendered** and **Hybrid** are generated by a GPU shader, not a CPU-generated bitmap or imitated glow made with Slate alone. `GlintPreviewCS` directly calls `GlintEvaluateSourceElement`, the same source-relative optical shape function consumed by runtime `GlintGhostCS`. This limits divergence between the editor's shape rendering and the runtime source-driven authored shapes.

## What the preview represents

The preview uses **one synthetic light** with editable X/Y position, preview exposure, and W/R/G/B source color. It is an optics preview and **not** an engine SceneCapture, HDR source detection test, source-tracking simulation, actual bloom/exposure simulation, or full lens-camera live game-view capture. HDR source extraction and post-process composition must still be tested in a real viewport. Preview display uses `1-exp(-color)` as a simple presentation transform; it is not Unreal's actual film tonemapper. Element size differences between the schematic symbol and analytic GPU shape are expected.

## GPU flow

`FGlintFlareEditorToolkit::TickPreview` samples the selected asset's current enabled elements and computes a CRC hash of packed elements, light position, source color, and preview exposure. Only changed requests enqueue a GPU pass; at rest the preview adds **no additional compute dispatch**. The renderer receives a bounded element array (maximum 12), a synthetic light, and a persistent 768×480 PF_FloatRGBA render target created with UAV support. It calls `RegisterExternalTexture`, creates an RDG UAV, and dispatches `FGlintPreviewCS` on the render thread. The target is then presented as a native Slate image brush.

The shader is compiled as a new global shader at editor startup. It can expose C++/HLSL binding and resource-state errors that our static checker cannot prove away. Do not retry a startup compilation failure without first examining the error.

## Camera interoperability

The editor preview is camera-system independent; normal Glint runtime views continue to support standard Camera Components, Cine Cameras and Gameplay Cameras through the shared rendered-view path. The experimental Gameplay Camera Rig *authoring node* and rig-evaluator lens blend remain future work, not a feature of Dev04.
