# Glint 0.8.7 | Protected HDR peaks, camera reprojection, and editor UX

## Basis and user QA

In UE 5.8.3, the user confirmed **47/47 native automation tests passing** on Glint 0.8.6.1 and that the project launches with SM6. Manual screenshots from Nov. 23 show: (1) Solo/Delete still blank, even when 0.8.6 text children are used; (2) `DebugSources 4` confirms bright sun disk is retained in filtered HDR, but tracked crosses favor clouds/ground; (3) radius 0/1/2 changes detection signal, with fewer stationary wobbles; (4) camera rotation produces jerky flare/source motion; (5) Weighted Blendables' picker offers both inline `Glint Lens Profile` creation and `Asset Reference`, whereas the requested UX is reference-only.

## What Unreal's native lens flare does differently

Epic documents its native lens flare as **image-based**, using image threshold, blur and optical patterns, not per-source temporal slot tracking. That explains a major architectural difference in smoothness: continuous image contributions follow light data spatially without enumerating and reassigning a limited set of persistent IDs. UE official reference: https://dev.epicgames.com/documentation/unreal-engine/post-process-effects-in-unreal-engine . Native `LensFlareIntensity`, `LensFlareThreshold`, `LensFlareBokehSize`, and `LensFlareBokehShape` remain separate engine settings. Glint's authored per-source optical elements need explicit anchors, so reproducing native image-field behavior wholesale would lose the authored source model. Continue to investigate a hybrid continuous/image-driven path for automatic effects versus source-anchored authored effects, rather than assuming extra smoothing can remove all candidate switches.

## Changes in this pass

1. **Two source candidates per 32×32 tile** in `GlintFindCandidatesCS`: the existing highest combined region-score winner, plus the **highest original unfiltered HDR peak**. This protects compact sources such as sun disks when a bright cloud or horizon wins the tile's region scoring. The HLSL group reduction tracks both in parallel and writes to adjacent X texels in an enlarged candidate texture. CPU C++ allocates doubled candidate width but retains the same tile dispatch count. This increases source-tracking scan/bandwidth costs, requiring GPU profiling after visual correctness.
2. **Compact-source ranking and anchor correction**: adjust the HDR score toward raw peak and contrast while keeping a lower-weight region term. For the region-selected candidate, blend the broad centroid back toward its actual HDR peak as a function of compactness, to avoid dragging a small sun toward an adjacent cloud. CPU parity (`FGlintSourceSelection::CalculateDetectionRank`) and native compact-source tests updated.
3. **Camera-rotation reprojection in temporal tracking**: store the previous view's **unjittered** `WorldToClip` matrix in view-state history. Build `previous clip -> current clip` each frame. On the GPU, reproject each tracked UV at **reverse-Z far depth** (directional/infinite-distance assumption) to the current view, before nearest-candidate matching and interpolation. During a dropout, a retained source now follows this camera projection instead of freezing at its old pixel position. The sustained challenger also reprojects its previous UV so camera movement does not continually reset its confirmation count. Camera cuts and history resets bypass reprojection. A CPU parity helper and native test verify identity, screen-space shift, and invalid projections. This is an approximation for nearby sources without depth; those still need reliable matching and perhaps future depth/motion-vector support.
4. **Weighted Blendables asset picker**: `UGlintLensProfile` now explicitly declares `NotEditInlineNew`, counteracting `UDataAsset` inline construction eligibility. Glint Lens remains a normal reusable `UDataAsset`, implements `IBlendableInterface`, and remains assignable by reference. Native reflection test verifies the class flag and interface. Existing serialized Lens assets should remain valid; manually verify the UI in UE5.8.
5. **Solo/Delete buttons**: instead of `SButton [ SBox [ STextBlock ]]` or registered PNG brushes, use `SButton.Text("S" / "X")` directly, the exact Slate path used by working named-element buttons. Keep fixed 24×24 hit targets, Solo/Delete functionality, and native layout smoke test. These are temporary functional letters, **not** final iconography. The test checks geometry, **not live Slate painting**; an Editor screenshot remains the acceptance gate. Do not claim this resolved until observed.
6. **50 native automation registrations** (previous 47 plus `WeightedBlendableAssetReferenceOnly`, `CompactSunPriority`, `CameraReprojection`), with the existing 47 preserved. No engine modifications or Probe dependency. No serialization changes to flare/lens properties.

## Risks and outstanding design decisions

- **Shader correctness and matrix orientation** require live SM6/viewport verification. The CPU helper validates expected row-vector clip mapping, but not actual `FViewMatrices` clip-space conventions at runtime. If movement worsens, disable reprojection temporarily for investigation rather than introducing compensating arbitrary pixel offsets.
- Some engine post-process pickers may still display a generic `Asset Reference` category along with other asset types. The aim is only to remove *inline Glint profile creation*; don't hide legitimate post-process material references.
- A compact very bright reflection remains a valid HDR source and may be selected over a sun that truly has lower HDR luminance. This is not solved by regional/peak scoring alone; consider an explicit optional directional-light source and/or a user-configurable source inclusion channel in a future pass.
- Native image-based lens flares are smoother partly because they avoid discrete source assignments. Explore a continuous HDR path for standard automatic effects while retaining precise source anchors for authored optics. This may be the long-term fix for rapid-camera-motion artifacting.
- The 50 native tests validate CPU policies, data, Slate layout and class flags, **not** GPU stability/actual widget painting. Manual QA remains essential.
